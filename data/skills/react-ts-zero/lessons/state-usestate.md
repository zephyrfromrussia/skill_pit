# Состояние: useState

## Идея
Обычная переменная внутри компонента не “живёт” между рендерами и не запускает перерисовку. Состояние (state) решает обе задачи: хранит значение между рендерами и сообщает React “нужно обновить UI”.
Hook `useState` возвращает пару: текущее значение и функцию обновления.

## Мини-конспект
- `const [value, setValue] = useState(initial)` — создаёт state.
- Обновление state запускает re-render.
- Для обновлений на основе предыдущего значения используй функциональную форму: `setCount((c) => c + 1)`.
- Hooks вызываются только на верхнем уровне компонента (не внутри `if`, `for`, вложенных функций).
- Типы часто выводятся автоматически, но иногда нужно подсказать: `useState<number>(0)` или `useState<string>('')`.

## Типовые ошибки
- Пишут `count = count + 1` вместо `setCount(...)`.
- Делают `setCount(count + 1)` несколько раз подряд и получают неожиданности (устаревшее значение).
- Вызывают `useState` внутри условий.
- Хранят в state то, что можно вычислить из props/другого state (лишняя синхронизация).

## Практика
- Реализуешь `Counter` с границами (min/max).
- Используешь функциональное обновление state.
- Сделаешь понятный UX: disabled-кнопки на границах.
