# Списки и ключи: рендерим коллекции

## Идея
Когда у тебя есть массив данных, UI обычно строится через `map`. React должен понимать, какой элемент списка “тот же самый” между рендерами. Для этого у каждого элемента должен быть стабильный `key`.
Ключ должен быть стабильным идентификатором данных, а не индексом массива.

## Мини-конспект
- Рендер списка: `items.map((item) => <Row key={item.id} ... />)`.
- `key` нужен только React; он не приходит в props компонента.
- Индекс массива как key приводит к багам при вставках/удалениях/пересортировке.
- Для локально создаваемых сущностей удобно делать id через `crypto.randomUUID()`.
- Данные списка лучше хранить в state как массив объектов.

## Типовые ошибки
- `key={index}` для списка, который меняется.
- Генерируют `key={Math.random()}` или `key={Date.now()}` при рендере → React считает, что всё новое.
- Мутируют массив в state вместо создания нового массива (`push`, `splice` без копии).

## Практика
- Реализуешь простой TodoList: добавить/удалить.
- Сгенерируешь стабильные id и корректные key.
- Типизируешь модель данных и операции.
